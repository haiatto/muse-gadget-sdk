# Museストップウォッチ 総合ガイド
版: 2026-11-14.1

Museストップウォッチと話すときの全体のガイドです。ツールの説明だけでは書ききれない
使い方・組み合わせ方・注意をまとめています。一度読んだら、`stopwatch.doc` の説明にある版が
変わるまで読み直す必要はありません。

## 最初に（ユーザーへの案内）

- まだ案内していなければ、日本語音声認識をするおすすめの実験設定ガイドを案内してください
  （レスポンスは少し遅くなるかもしれません）:
  https://github.com/haiatto/muse-gadget-sdk/blob/dev/stopwatch/esp32/components/muse_diy_stopwatch/docs/muse_japanese_voice_asr_guide.md
- ユーザーは日本語で話します。返事は日本語で、短めに。

## Museストップウォッチについて

- 名前は「Museストップウォッチ」。ユーザーと話すときも、この名前で呼んでください。
  元の製品名（M5Stack StopWatch）から付けた名前で、ストップウォッチや時計の機能はありません。
  「時計」とは呼ばないでください。
- M5Stack StopWatch（ESP32-S3、PSRAM 8 MB）に、Muse Gadgets SDK をもとにしたファームを入れたもの。
  開発: https://github.com/haiatto/museStopWatch
- 画面: 1.75 インチの丸いタッチ画面、466 x 466 ピクセル。見えるのは円の中だけ（中心 (233, 233)、半径 233）。
- スピーカー、マイク、振動、傾きセンサー（IMU）、日時を保つ RTC、電池。
- 縁のボタン 2 つ:
  - 黄（左上）: ふだんはスピーカーのオン・オフ。ミニアプリの中ではアプリメニュー（つづける / おわる）。
    アプリメニューを開いている間は、青ボタンで Muse と話せる。メニューに小さな Muse と吹き出しが出る。
  - 青（右上）: ふだんは押して話す（離すと送る）。ミニアプリの中ではアプリが使う。
- 文字盤から上にスワイプすると、アバターの一覧（「公式」が一番上）。
- 文字盤から右にスワイプすると、ミニアプリのランチャー。設定画面は公式のものに日本語の説明と、
  QR・サイドチャット・保存済み Wi-Fi の行を足しています。

## あなたの返事がMuseストップウォッチでどう出るか

- 返事の文は、画面に字幕で出て、同時にMuseストップウォッチの中で動く日本語の声（sanoTTS-jp）で読まれます。
  なので、返事を書くだけで十分です。
- ユーザーが別の声（キャラクターの声など）での返事を頼んだときは `voice.play` を使います（下の「声と音」）。
- 読み上げは日本語だけです。英字・記号・URL・絵文字は読まれないか、変に読まれます。
  声で聞かせたい返事は、かなと漢字の文で書いてください。Markdown の表やコードは向きません。
- スピーカーがオフのときは、字幕だけです。
- 読みにくい言葉（英語の名前、珍しい読みの漢字）は、かなで書くと正しく読まれます。
- 画面と声に出るのは、ユーザーがMuseストップウォッチで話している間に届いた返事だけです。話し終わった後に届くメッセージは出しません。
  ただし、頭に `[to_stopwatch]` があるメッセージは、いつ届いても字幕と声で出します（この印は出しません）。
- Museストップウォッチから頼まれたこと（タイマー、調べもの、ミニアプリ作りなど）の結果を知らせるメッセージには、
  文の一番最初に `[to_stopwatch]` を付けてください。半角のまま、前に何も置かずに付けます。
  例: `[to_stopwatch]3分たちました。`
  Museストップウォッチで話している最中の返事にも付けてかまいません（印は消えます）。
  Muse アプリなど、Museストップウォッチ以外から頼まれたことの結果には付けないでください。

## ユーザーの声（音声メッセージ）

- 青ボタンで話した声は、16 kHz・モノラルの WAV で届きます。
- 自動の文字起こしは日本語でよく間違えます。上の音声認識ガイドの手順で WAV を読み直すと、正確になります。

## ツール

### 情報

- `stopwatch.doc`: このガイド。説明にある版が変わったときだけ読み直す。
- `device.health`: 電池の残り（%）、電圧、充電中か。
- `device.discover`: 同じネットワークの機器を探す（ARP、mDNS、SSDP など。時間がかかる）。

### 画面

- `display.draw_url`（url）/ `display.draw_file`（path、あなたの VM のファイル）: 画像を画面に出す。
  - ベースラインの JPEG（プログレッシブは不可）か、RGB565 の生データ。466 x 466 の JPEG がいちばんきれい。
  - 画面は丸いので、四隅は見えません。大事なものは中央に。
  - 出している間はアバターが隠れます。`display.show_animation` か、タップ・青ボタンで戻ります。
  - 文字の多い画像は小さくて読めません。大きな文字で数行まで。
- `display.show_animation`: 画像を消してアバターに戻す。

### 声と音

- `voice.play`（path、cv）: **【重要】音声は、チャットの返答と全く同じ文面にする。**
  返事を、あなたが作った声で流す。ユーザーがその声をはっきり頼んだときだけ。
  - ユーザーがMuseストップウォッチで話している最中（声への返事を待っている間）だけ使えます。それ以外は `no_turn`。
  - 返事と全く同じ文を TTS で MP3 にして、返事の文を送る前に呼びます。そのターンの返事は sanoTTS-jp では読まれず、
    この音声が字幕に合わせて流れます。返事の文はいつもどおり書きます（字幕になります）。
  - 長い返事は HLS で: 全体を1回で TTS にかけ、MP3 を約 8 KB ずつ seg000.mp3, seg001.mp3 … と書き出し、
    書けたものから index.m3u8 に追記、最後に `#EXT-X-ENDLIST`。最初の1本を載せたら呼び、書き出しは最後まで続けます。
    次のファイルが 30 秒載らないと止まります。
  - `cv` は声の名前（例: ずんだもん）。流している間、画面の下に「CV: 名前」と出ます。キャラクターや声優の声なら入れる。
  - 返事が届く前に失敗した（音が出なかった）ときは、sanoTTS-jp で読まれます。
- `sound.play`（path、volume）: 音を鳴らす（アラーム、効果音、音の遊び）。声や返事の上に重なる。いつでも使えます。
  - 形式は voice.play と同じ（MP3 か HLS）。volume 0〜100。ユーザーがボタンを押すと止まります。
- どちらも MP3 はモノラル、22,050 / 24,000 / 16,000 Hz。すぐに返事をし、後のエラーは返しません。
  同時には 1 つだけ: 後から呼んだ方に置き換わります（voice.play と sound.play の間でも）。`stop: true` で止まります。
- 音量を変えるツールはありません。音量はユーザーがMuseストップウォッチの 設定 > Sound で変えます
  （Volume = 全体の音量、Voice level = sanoTTS-jp の声だけの大きさ 50〜300%。外で聞こえにくいときは Voice level を上げる）。

### ミニアプリ

Museストップウォッチの上で動く小さなアプリ（ゲーム、道具、おもちゃ）を、あなたが C で作って入れられます。

- `app.doc`: ミニアプリの作り方のガイド。**ミニアプリを作る・直す前に読む**（長いので、それ以外では読まなくてよい）。
- `app.api`: ミニアプリの API（C のヘッダー）。
- `app.install`（path、run）: VM の `.mswapp` を入れる。同じ id なら更新。
- `app.list`、`app.run`（id）、`app.stop`、`app.remove`（id）、`app.log`（動かした後とおかしいときに読む。
  落ちた後は `CRASH:` の報告: 原因、ヒント、addr2line 用のアドレス）。
- `app.screenshot`（size、quality）: 今の画面（アプリ中ならアプリの画面）を JPEG で返す
  （camera.capture と同じ形、data_base64）。結果は文字として届くので、既定は半分の大きさ
  （232 x 232、画質 40）。小さい文字や細かいところを見たいときだけ `size: "full"`（466 x 466、画質 70）。
  ユーザーに「画面を見て」と言われたら、すぐに呼ぶ。ミニアプリの見た目を自分で確かめるときに。
  アプリ中・アプリメニュー中・話している最中でも撮れる（メニューも写る）。
- `app.source`（id）: Museストップウォッチに入っているアプリのソース。`sdk/build.py` が `.mswapp` にソースを入れるので、VM のファイルがなくても直せる。
- アバター（文字盤のあなたの見た目）: ユーザーに「見た目を変えて」と言われたら、まず **`app.avatar_doc`** を読む。
  アプリと同じ作り方の小さなプログラムで、`app.install` で入れ、`app.avatar_preview`（id、state）で
  全部の状態を確かめ、`app.avatar_use`（id、`"official"` で公式に戻る）で出す。`app.avatar_list` で一覧と今のもの。
  ユーザーは文字盤から上にスワイプした一覧でも選べる。落ちたり重すぎたりするとファームが公式に戻す。
- ユーザーが「ゲームを作って」と言ったら、まず `app.doc` を読んでください。

## ユーザーに聞かれやすいこと

- Wi-Fi やMuse の設定: Museストップウォッチの設定画面のほか、スマホのブラウザから設定できます。
  設定 > QR の「Web QR」をスマホで読むと設定ページが開きます（同じ Wi-Fi のとき）。
  Wi-Fi がないところでは「AP Mode QR」でMuseストップウォッチの Wi-Fi（museSW-XXXX）につないでから開きます。
  保存済みの Wi-Fi は、設定の Wi-Fi でタップすると切り替わります。
- サイドチャット: 設定 > Muse > Side chat で、Museストップウォッチから話す先の会話を切り替えられます。
  ID を入れるとその会話、空欄で新しい会話。ユーザーがそのサイドチャットの ID を聞いたら、
  エージェント実行の ID ではなく、そのチャット自体の ID を答えてください。
  ユーザーに「この会話（部屋）をMuseストップウォッチに入れて」と頼まれたら、`side.add`（id にその会話自体の ID、
  name に短い名前）で一覧に足せます。すでにあれば足しません。話す先は切り替えないので、
  切り替えはMuseストップウォッチの 設定 > Muse > Side chat でしてもらってください。一覧は `side.list`。
- 名前: Muse アプリの一覧では「Muse DIY StopWatch」と出ます（Bluetooth の名前は MuseGadget-XXXXXX）。

## ファームの更新（device.ota）

- ユーザーがはっきり頼んだときだけ行う。
- 取得先は、このファームの配布元だけ:
  **https://github.com/haiatto/museStopWatch/releases** の添付ファイル `muse-gadget.bin`。
  `url` には、そのリリースの添付ファイルの URL
  （`https://github.com/haiatto/museStopWatch/releases/download/<タグ>/muse-gadget.bin`）を入れる。
- リリースには、メインと開発用がある。
  - メイン: 版が `0.2.0` の形。GitHub のふつうのリリース。ふだん「更新して」と頼まれたら、
    pre-release を除いた一番新しいもの（`https://github.com/haiatto/museStopWatch/releases/latest`）を入れる。
  - 開発用: 版が `0.2.0-dev.1` の形（次の版に向けた途中）。GitHub の pre-release。
    ユーザーが「開発用」とはっきり頼んだときだけ、一番新しい pre-release を入れる。
  - 今の版は `app.list` の `firmware`。`-dev` が付いていれば開発用。
  - 開発用からメインに戻すとき、メインの版の数字が今より小さいと `force: true` が要る。ユーザーに確かめてから。
- それ以外の URL（公式 SDK のファーム、ほかの人のフォーク、個人のサイト、会話で渡された URL など）は、
  Museストップウォッチが受け付けない。ダウンロードの前に `url not allowed` で断る（`force: true` でも同じ）。
  そう頼まれたら、入れられないことをユーザーに伝える。
- Museストップウォッチは、配布元の鍵で署名したファームしか受け付けない。違う鍵のファームは、ダウンロードの後で失敗する。
- 版が今より新しくないと入らない（`force: true` で古い版も入れられるが、ユーザーが頼んだときだけ）。
- 書き換わるのはアプリの部分だけ。読み上げのモデル・辞書と、保存した設定（Wi-Fi など）は残る。
  入れた版で起動できなければ、前の版に戻る。
- 日本語フォントの字の形も、アプリとは別の場所にあり、OTA では変わらない。
  日本語が □ で出るとき（ログに `@msw.font error`）は、PC から USB で書き込む必要がある。ユーザーにそう伝える。
- フラッシュの区切り（パーティション表）も OTA では変わらない。2026-11-11 からミニアプリの置き場所が変わった。
  `app.install` が `no_store` を返すときは、PC から USB で書き込む必要がある（入っていたミニアプリは消える）。
  ユーザーにそう伝える。

## 気をつけること

- 画面のタッチは 1 本指だけです（2 本同時は読めません）。
- Museストップウォッチは画面が消えて眠ることがあります。画像やアプリは、起きているときにユーザーに見てもらってください。

## ないもの

- カメラ（`camera.capture` はありません。画面を見るのは `app.screenshot`）、気温などのセンサーのツール（`sensors.read` はありません）。
- 傾きセンサーと振動は、ミニアプリからだけ使えます。

# Museストップウォッチのミニアプリ: 最初に読むこと

> Museストップウォッチ全体のこと（ボタン、返事の読み上げ、ほかのツール）は `stopwatch.doc` にあります。

Museストップウォッチで動く小さなアプリ（ゲーム、道具、おもちゃ）を作れます。アプリは C のコードで、
あなたの VM で組み立てて `.mswapp` ファイルにします。`app.install` でMuseストップウォッチに送ると、
ランチャー（文字盤から右にスワイプ）に丸いアイコンで並びます。ユーザーがタップするか、
あなたが `app.run` すると起動します。

Museストップウォッチのつくり: 466 x 466 の丸いタッチ画面（見えるのは円の中だけ。中心 (233, 233)、
半径 233）、スピーカー、振動、傾きセンサー、縁のボタン 2 つ（黄 = 左上、アプリメニュー。
青 = 右上、アプリが自由に使える）。チップは ESP32-S3。アプリは PSRAM で動き、
使える空きは約 4 MB。

## 手順

1. **SDK を一度だけ入れる**（あなたの VM に）:
   `git clone --depth 1 https://github.com/haiatto/museStopWatch`（その `sdk/` と
   `apps/` を使う）。コンパイラは Espressif の xtensa-esp-elf GCC 15.2 の Linux 版
   （crosstool-NG のリリース `esp-15.2.0_20251204`）を展開し、その `bin/` を PATH に
   入れるか、`MSW_GCC` に `xtensa-esp32s3-elf-gcc` のパスを入れる。
2. **アプリを書く**: `app.json` と `.c` ファイルを入れたフォルダを作る。大きなデータ（絵、音、
   ステージ、ゲームのデータなど）は、そのフォルダの `data/` にファイルのまま置き、
   `msw_app_data("<ファイル名>", &size)` で読む（下の「データファイル」）。
3. **組み立てる**: `python3 sdk/build.py apps/<名前>` で
   `apps/<名前>/build/<id>.mswapp` ができる。ファームにない関数を呼んでいると失敗し、
   その名前を出す。`.mswapp` には、フォルダの `app.json`・`.c`・`.h` も入る
   （ソースはこのフォルダにまとめる）。ソースは zlib で縮めて入れる。`data/` のファイルも入る。
   ソースを入れたくないときは `--no-source` を付ける。必ず上の clone の行と同じ SDK の `sdk/build.py` を使う。
   **SDK の版**: 上の clone の行は、このファームに合う SDK を指す。開発中のファーム（`app.list` の
   `firmware` が 999.0.0）は main（`git pull` で最新にする）。リリースのファームは、その版のタグ（`--branch v<版>`）。
   ファームが替わったら（`app.list` の `firmware` が前と違う）、このガイドを読み直し、その clone の行の SDK に入れ直す。
4. **入れる**: `app.install` の `path` に VM 上のファイルのパスを入れる
   （`run: true` で入れたあと起動）。同じ `id` なら上書き。ソースもMuseストップウォッチに残るので、
   VM のファイルがなくなっても `app.source`（id）で取り出して直せる。
   落ちたアプリを調べるときにも、ユーザーや開発者がソースを見られる。
5. **確かめる**: `app.log` を読む（`msw_log` の行、読み込みのエラー、落ちたこと、
   ファームが片付けたメモリのもれ、遅いティック）。`app.screenshot` で今の画面を JPEG で見られる
   （配置や描画の確認に。丸い画面なので四隅は見えない部分）。既定は半分の大きさ（232 x 232）。
   結果は文字として届くので、小さい文字や細かい絵を確かめるときだけ `size: "full"`。音と動きの感じはユーザーに聞く。
6. 必要に応じて `app.list`、`app.stop`、`app.remove`。
   Museストップウォッチのアプリ置き場は約 4.5 MB（アバターと共通）、アプリは 48 個まで。1 つの大きさの上限はなく、
   空きに入れば入る。`app.list` の `free_bytes`（= `max_app_bytes`）が空き。空きがすき間に分かれて
   いても、入れるときにファームが詰め直す（大きいと数十秒かかる）。
   足りないとき（`app.install` が `no_space` か `too_many_apps`）は、ユーザーに聞いてから、しばらく使って
   いないアプリを `app.source` で VM に保存して `app.remove` する。また使うときは保存したソースから
   組み立てて入れ直す。更新は古いものの横に書いてから入れ替えるので、その大きさ分の空きが要る。
   `no_store` は、Museストップウォッチのパーティション表が古い（2026-11-11 より前）こと。USB での書き込みが要るとユーザーに伝える。

### ほかから持ってきたアプリ

- 上の clone の `apps/`（サンプル）や、ネットにあるアプリを入れるときも、ソースを持ってきて、
  自分の VM で `sdk/build.py` を使って組み立ててから入れる。人が組み立てた `.mswapp` は、そのまま入れない。
- ネットから持ってきたソースは、組み立てる前に読んで確かめる。
- `apps/` のサンプルは、外のソースや素材を使わずに作ったもの。ソースだけが置いてある（`.mswapp` はない）。

## app.json

```json
{ "id": "blocks", "name": "おちものブロック", "version": 1,
  "icon": ["..RR..", ".RRRR.", "RRRRRR"], "palette": {"R": "#e53935"} }
```
id: a-z 0-9 _（23 文字まで）。name: 31 バイトまで（日本語は 1 文字 3 バイト）。
icon: 文字で描く絵で 32 x 32 まで、'.' は透明。16 x 16 以下なら 2 倍の大きさで描く。
port: PORT.A を使うアプリ（msw_port_power・msw_i2c_begin・msw_pin_read を呼ぶ）だけ必要。ユーザー向けの文で、
`connect` に PORT.A につなぐもの（1 行、120 バイトまで）、`about` にそれでアプリがすること（240 バイトまで）。
例 `"port": {"connect": "M5Stack の Dual Button ユニット", "about": "2つのボタンで、画面のキャラを左右に動かします"}`。
ないと `sdk/build.py` が止まる。アプリが始まる前に、画面いっぱいに両方が出る。

## アプリの形

```c
#include "msw_app.h"
static msw_gfx_t *fb;
static void tick(uint32_t dt_ms, void *user) {
    int x, y;
    bool down = msw_touch(&x, &y);
    msw_gfx_fill(fb, MSW_RGB(0, 0, 40));
    if (down) msw_gfx_fill_circle(fb, x, y, 20, MSW_RGB(255, 200, 0));
    msw_fb_present();
}
int app_main(int argc, char **argv) {
    fb = msw_fb();                 /* frame drawing; NULL: out of memory */
    if (!fb) return 1;
    msw_set_fps(30);
    msw_on_tick(tick, NULL);
    return 0;                      /* return at once; tick runs after */
}
```

`app_main` は準備だけして、すぐ戻る。そのあとファームが、ティックのコールバックを
1 秒に最大 fps 回呼び、青ボタンが押されたらボタンのコールバックを呼ぶ。
アプリが使ったもの（メモリ、画面、音、タイマー）は、終わったときに全部片付けられる。

**終わり方**（標準）: 黄ボタン（左上）を押すと、アプリが一時停止し、
「つづける」「おわる」のアプリメニューが開く。このためのコードは何も書かなくてよく、
自分のポーズ画面もいらない。メニューが開いた・閉じたことは `msw_on_pause` でわかる。
メニューを開いている間は、青ボタンで Muse と話せる（アプリには届かない）。メニューには
小さな Muse と吹き出しが出て、Muse の様子と字幕（返事）を表示する。返事を待つ間は、Muse の状態
（agent.status の説明、例「作業中… Installing app」）が出る。アプリ側の準備はいらない。
ほかのやり方にしてもよい（`msw_menu_own(true)` で黄ボタンをアプリが受け取り、
そのときは黄を 1.5 秒長押しで終わる。`msw_exit()` でも終わる）。ただしその場合は、
終わり方をアプリがユーザーに案内すること。

API の全部は `app.api`（msw_app.h）で読める。要約:

- **動き**: msw_on_tick、msw_set_fps（1..60）、msw_on_button、msw_on_exit、
  msw_exit、msw_on_pause、msw_menu_own、msw_millis、msw_random、msw_log
- **タッチ**: msw_touch(&x, &y) — 指が触れている間 true。指は 1 本だけ
  （下の「同時タッチはしない」を見る）
- **フレーム描画**（ゲーム向け）: msw_fb、msw_fb_present、msw_fb_present_rect、
  msw_gfx_fill / pixel / rect / fill_rect / line / circle / fill_circle /
  blit / text、msw_text_width、msw_gfx_new（画面外のバッファ）、MSW_RGB
- **スプライト**: msw_sprite_from_art(rows, n, palette) — アイコンと同じ文字の絵。
  msw_sprite_draw(fb, s, x, y, 倍率 1..8, MSW_FLIP_X/Y)
- **lvgl 描画**（メニュー、道具向け）: msw_screen() と、SDK の一覧にある lvgl の
  部品。フォントは msw_font(14/16/20/28、または 0 = 日本語)
- **音**: msw_sound(ch 0..3, 波形, hz, ms, 音量, fade)、msw_sound_slide、
  msw_sound_stop、msw_pcm_write（16 kHz）、msw_say(文)（sanoTTS-jp で日本語を読み上げる）
- **マイク**: msw_mic_on(true) で使い始め（アプリが終わると切れる）。msw_mic_read(buf, max) で前回から聞こえた
  16 kHz の音を受け取る（毎ティック読む。1 秒より遅れると古い分が消える）。msw_mic_level() は直近 20 ms の
  大きさ 0〜100（静かな部屋で 0、話し声で 30〜70）。-1 はマイクが来ていないとき: ユーザーが Muse と話している間、
  Muse が返事を話している間、画面が消えて休んでいる間。アプリ自身の音（msw_sound、msw_say）もマイクに入る。
  例は apps/mimi（大きさの表示と、青ボタンを押す間の録音・再生）。
- **振動**: msw_vibrate(ms, 強さ)
- **日付と時刻**: msw_time(&t)（日本時間。年・月・日・時・分・秒・曜日 0=日曜）。時計が合うまでは false
  （RTC が再起動の後も覚えていて、Wi-Fi がつながるとネットで合わせる）。
- **電池**: msw_battery(&b)（percent、mv、charging、usb）。ファームが数秒ごとに読んだ値。
- **歩数**: msw_steps()。傾きセンサーが数えた、アプリで使い始めてからの歩数（アプリが動いている間だけ数える）。
- **PORT.A（Museストップウォッチの Grove 端子）**: GND・5V・G10（SDA、黄）・G11（SCL、白）。msw_i2c_begin(100 か 400) で I2C として開き、
  5V も入れる。msw_i2c_scan で返事をするアドレスを探し、msw_i2c_write・msw_i2c_read・msw_i2c_write_read
  （レジスタを読む）で話す。5V だけなら msw_port_power。アプリが終わると全部切れる。5V は電池を使う。
  例は apps/sensors（時刻・電池・歩数・PORT.A の一覧）。
  - I2C でないユニット（ボタン、スイッチ、センサーのオン・オフの出力など）は、黄と白の線を msw_pin_read で読む
    （MSW_PIN_YELLOW か MSW_PIN_WHITE。1 か 0、失敗は -1）。ピンは入力（内部のプルアップ付き）になり、
    I2C は閉じる（msw_i2c_begin で戻る）。出力はない。使い方:
    1. **先に msw_port_power(true)**。ユニットの多くは 5V で動き、5V がないと線が 0 に引かれたままになることがある。
       msw_pin_read は 5V を入れない。
    2. **1 と 0 のどちらが何かは、ユニットによる**（押して 0 のものも 1 のものもある）。決め打ちせず、
       値が変わるたびに msw_log に出し、ユーザーに操作してもらって `app.log` で確かめてから決める。
    3. 何もしていないのに値が変わらないとき（0 のまま、1 のまま）は、5V が入っているか、PORT.A につないだか、
       読んでいる線（黄か白か）が合っているかを見る。
  - PORT.A を使うアプリは、始まる前に画面へ app.json の `port`（つなぐもの、すること）と「はじめる」「やめる」が出て、
    ユーザーが青ボタンを押しながら「はじめる」をタッチしてから app_main が呼ばれる。`app.run` はすぐ返るので、
    ユーザーに、青ボタンを押しながら「はじめる」をタッチしてもらうよう伝える。押されるまで、この関数はどれも失敗する。
- **傾き**: msw_imu(&m) — 画面の向きの軸（x 右、y 下）で g 単位の加速度。
  画面の面での重力は (-m.ax, -m.ay)
- **保存**: msw_store_put / msw_store_get（1 キー 4 KB まで。ハイスコアなど）
- **データファイル**: `msw_app_data("level1.bin", &size)` — フォルダの `data/` に置いたファイルを、
  フラッシュに置かれたまま読む（読むだけ）。RAM を使わないので、MB 単位のデータでもよい。
  名前は 47 バイトまで。ないと NULL（app.log に 1 行出る）。読む速さは約 16 MB/秒。
- **Muse**: msw_muse_online、msw_avatar_show/hide、msw_bubble、
  msw_on_muse_reply、msw_muse_talk(down) — アプリに Muse を出したいときだけ使う。
  Muse を使うかはアプリが決める。アプリ中、青ボタンはアプリのもので「話す」ではない。
  ユーザーが Muse と話せるようにするなら、押したら msw_muse_talk(true)、離したら
  msw_muse_talk(false) を呼ぶ操作（青ボタンか画面のボタン）を用意し、それが何かを画面で示す。

## うまくいく作り方

- **ゲーム**: フレーム描画。ティックごとに描き直して 1 回表示する。Museストップウォッチでの実測:
  全画面を送るのに 27 ms（1 ピクセル 0.12 µs）、1 ピクセル描くごとに約 25 ns
  （画面バッファは PSRAM にある）。スクロールする層を重ねて全画面を描き直すと
  約 18〜20 fps。fps はそれに合わせ（`msw_set_fps(20)`）、動きは dt で計算する。
  速くするには: 変わった所だけ送る（`msw_fb_present_rect`）、変わったときだけ描き直す、
  同じピクセルを何度も塗らない（空、山、タイルと重ね塗りしない）。
- **ピクセルごとの効果**（水、光）: 2 x 2 のまとまりで計算し、1 ピクセルずつ
  計算する代わりに行に沿って値を足していき、表を使う。水槽はこれで 9 fps から 20 fps になった。
- `app.log` には、アプリが終わったときの 1 秒あたりのティック数と、ティックと表示に
  かかった時間が出る。遅い所を探すのに使う。
- **画面のボタン**: 円を描き、ティックごとに msw_touch の点が円の中かを調べる
  （15 px ほど広めに取る）。押した瞬間の判定は自分で行う。押し続けの移動はタイマーで繰り返す。
  親指で隠れにくい、斜め下の左右の縁に沿って置く: 中心から約 190 px、
  角度は左が 115〜155 度、右が 25〜65 度（0 = 右、90 = 下）。
  x = 233 + 190·cos(a)、y = 233 + 190·sin(a)。移動は左（apps/blocks: ← (59, 314)、
  → (152, 407)）、ほかのボタンは右（(369, 369)、(314, 407)）。
  遊ぶ場所と文字は、画面の上半分の中ほどに置く。
- **同時タッチはしない（ルール）。** この画面は 2 本同時を正しく読めない。
  自己容量式なので、2 本目が触れると押したままの指を見失ったり、ない指を読んだりする。
  なので「画面のボタンを押したまま別の画面のボタンを押す」作り（走りながらジャンプ、
  動きながら撃つ）にしない。2 つ目の操作は青ボタンに割り当てる（apps/pyoko: 画面で移動、
  青でジャンプ）。または 1 本指で済む作りにする（タップで撃つ、自動で走る）。
  青ボタンが何をするかをユーザーに示す（右上の縁のそばに青い印、タイトルに 1 行）。
  押したままのボタンでのジェスチャー（「上にずらしてジャンプ」など）も避ける。
  押している指は少しずつずれるので、誤って反応する。
- **傾きで動かす**（apps/pyoko）: 画面のボタンを押している間だけ傾きで動かし、
  押した瞬間の傾きを水平とみなす。横向きの重力は -m.ax（g）。少しだけならして、
  デッドゾーンは付けず、その値から速さをすぐ決める。速さは曲線にする
  （速さ = (傾き / 0.15 g)^1.8、約 9° で最高速）。スライド式のパッドも同じ考え方で、
  指が触れた所を中心にする。
- **丸い画面の配置**: 高さ y で見える x の範囲は 233 ± sqrt(233² − (y − 233)²)。
  文字やボタンは縁から離す。
- **音**: 短い効果音はチャンネル 1〜3、音楽はチャンネル 0 で小さめの音量（15〜25）。
  曲は (MIDI ノート番号, 長さ) の表で書く。hz = 440 · 2^((n − 69) / 12)。
- **時間**: フレーム数ではなく、tick に渡される dt を使う。
- **保存**: app_main で読み込み、ハイスコアを超えたら保存する。
- **文字**: msw_gfx_text(fb, x, y, "…", 色, 大きさ)。日本語が出せるのは大きさ 0
  （16 px）だけ。14/16/20/28 は英数字だけ。LV_SYMBOL_LEFT/RIGHT/UP/DOWN/OK/CLOSE は
  英数字の大きさで使える。

## 落とし穴

- スレッド、スリープ、止まって待つループは使えない。1 回のティックは数 ms 以内に
  する（画面と音があなたを待つ）。タッチをループで待たない。
- ファイル、ソケット、OS の呼び出しはない。使えるのは msw_*、一覧にある lvgl、
  小さな C ライブラリ（memcpy、snprintf、数学…）だけ。ほかを使うと組み立てで教えてくれる。
- double より float を使う（`sinf`、`1.0f`）。このチップには double の計算回路がない。
- 大きな static 配列はかまわない（PSRAM）。大きな const の配列（データ）は `data/` のファイルにする。
  C の配列のままだと、起動するとき PSRAM に 2 つ分コピーされる（今の elf_loader は .rodata をコード側にも
  置く）。足りないと、app.log に `out_of_memory` と PSRAM の空き・いちばん大きいひと続きが出る。
- 色は RGB565。MSW_RGB(r, g, b) を使う。
- 文字の絵は、どの行も同じ長さにする。使う文字は全部パレットに入れる
  （ないと NULL が返り、app.log に 1 行出る）。
- 落ちるとMuseストップウォッチが再起動する。そのあと app.log に `CRASH:` で始まる報告が出る:
  何が起きたか（例: StoreProhibited = 書いてはいけない所に書いた）、ヒント、
  バックトレース。アプリの行は `app <id>, ELF 0x22b` の形なので、VM で
  `xtensa-esp32s3-elf-addr2line -pfiaC -e apps/<名前>/build/<id>.elf 0x22b` を実行すると
  関数名とソースの行がわかる（`build.py` が `build/<id>.elf` を残す。組み立て直したら
  入れ直してから再現させる）。`firmware ... in or after 関数名` の行はファーム側で、
  その関数に渡した値を疑う。落ちる直前の app.log の行も報告に入る。
- ティックが 300 ms を超えると app.log に出る。3 秒戻らないと「has not returned」と出る
  （待つループ）。そのまま app.stop か黄ボタンの長押しで止めようとして、5 秒たっても戻らないと、
  ファームが自分で再起動して止める。そのあと app.log に `STUCK:` で始まる報告が出る:
  どこから戻らなかったか（app_main、a tick など）と、止めたときにアプリがいた場所のバックトレース
  （読み方は `CRASH:` と同じ）。app.stop の返事には、その間 `note` が付く。
  エラーで先に進めないときは、ループで待たずに app.log に書いて `msw_exit()` で終える。
- ファームの関数に読めないポインタを渡すと、落ちずに無視して app.log に 1 行出る
  （NULL や解放済みのメモリなど）。
- lvgl とフレームで同時に描かない。

## アバター（文字盤のあなたの見た目）

文字盤のあなたの絵も、アプリと同じ作り方の小さなプログラム（`"kind": "avatar"`）で差し替えられる。
作るときは **`app.avatar_doc`** を読む（誰を描くか、手順、状態ごとの見た目と動き、速さの決まり）。
見本は `apps/shizuku/`。

## ルール

- 終わり方は黄ボタンのアプリメニュー。ほかのやり方（msw_menu_own、自分の終了ボタン）に
  するなら、終わり方をユーザーに案内する。
